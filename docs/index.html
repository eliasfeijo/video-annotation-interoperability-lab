Video Annotation Interoperability Lab

An auditable investigation of the existing standards stack for graphical video annotations. The lab asks when geometry becomes predictable, interoperable, and mechanically checkable — and records where guarantees stop.

One-sentence research statement: a reproducibility lab testing whether the IIIF/Web Annotation/Media Fragments/SVG stack can express portable temporal graphical video annotations without a new vocabulary, and where that stack becomes predictable, interoperable, and checkable — conditional and version-scoped. Source: capstone §1 + post-research-plan §6.3 Hero

If this page and any owning research document disagree, the owning document wins (spec §1).

Research question

Under which conditions does the geometry of graphical content painted onto IIIF Presentation Canvases become predictable, interoperable, and mechanically checkable?

Motivation: using W3C Web Annotation + Media Fragments + IIIF Presentation 3.0 Canvas/Painting + SVG to draw annotations over video without inventing a new annotation vocabulary. The standards permit this; they do not fully specify what the resulting geometry means. Source: capstone §1–§2; framing documentation-conventions §T-5

Result — conditional

A constrained profile can make static graphical overlays on IIIF video Canvases mechanically predictable when explicit coordinate systems (explicit viewBox) and same-aspect composition are enforced — and those conditions are checkable. The broader goal of interoperable animated/temporal annotations remains outside the guaranteed profile because real consumers do not consistently honor the required temporal/compositional semantics — for the tested Canvases/bodies/engines/consumers/versions (#t=10,20 Canvas-target, Ramp 5.1.1 vs Mirador 3.4.3, Chromium 151.0.7922.34 / Firefox 153 / WebKit 26.5).

The word “interoperable” is bounded to the constrained profile / resource-side geometry conditions above (R-S1 explicit viewBox, R-S4 same-aspect), never as “works across arbitrary real-world IIIF viewers.” Consumer-side certification is BLOCKED — no capable consumer exists today. Source: capstone §1, §9, §11 → profile R-S1, R-S4 → n4-safe-subset

Key findings

Version scope shown inline per spec MUST-02. Each finding traces to capstone §5 and owning report.

1. Explicit viewBox restores determinism PROFILE R-S1

With viewBox="0 0 1000 1000" on the SVG root, all region-painting mechanisms (nested <svg>, <img> default/fill, object) agree with I-REGION-VIEWPORT — 40 viewBox cells in E15, confirmed 62/62 tri-engine E17 F1. Without it, three coexisting readings appear (I-REGION-VIEWPORT vs I-INTRINSIC-STRETCH vs object-fit), engine-uniform (E17 F2/F3).

Source: e15-report §4 + e17 F1–F3 + profile R-S1 [PROFILE] on SVG 1.1 §7.7–7.12 + CSS Images 3 §4.5. Evidence: evidence/e17/cross-engine-matrix.json

2. 62/62 cross-engine replication [BROWSER]

Geometry matrix unanimous in Chromium 151.0.7922.34 / Firefox 153.0 / WebKit 26.5 via Playwright 1.62.1 (Windows). Version-scoped browser behavior, not normative law — does not upgrade any row to [NORMATIVE].

Source: e17-report:20–31 + cross-engine-matrix.json

3. No-viewBox hazard is engine-uniform OPEN eliminable

No engine choice rescues it. Intrinsic size (naturalWidth 1000×1000 vs Chromium 267×150 for viewBox-only per e15 §4.3/e17 F3) describes a bitmap size, not a coordinate contract — hence R-S1 rejects viewBox-less bodies, R-S7 excludes intrinsic reliance.

Source: e15 §4.3 + e17 F3

4. Same-aspect safe subset PROFILE R-S4/P5a

When Tw·Hb == Th·Wb (painted) / W'·H == H'·W (replacement), every reasonable fit coincides mathematically: unique uniform scale k=Tw/Wb=Th/Hb, zero letterbox offsets/crops. Mismatch diverges up to ~386 Canvas units (landmark-spot-check.json) / ~405 synthetic (profile Part 14 Example B). Same-aspect twins coincide twinMatchesFill && twinMatchesContain, tri-engine fitsCoincide true (E17 F6). Under P5a, leaf-PAR collapse becomes unreachable.

Source: n4-safe-subset Part 2 P5a → profile R-S4 + e17 F6

5. Consumer limitations — version-scoped [CONSUMER]

Ramp 5.1.1 error boundary on any secondary painting body (SVG/raster/Canvas-as-body, V4–V7) Cannot set properties of undefined (setting 'id'); Mirador 3.4.3 silent drop (M2/M3 zero overlay elements). D1 interaction probe (Chromium 151, consumer-owned click(.vjs-big-play-button), 4 valid drives): Ramp NOT-HONORED for #t=10,20 (settled 2.65/2.64 vs control 2.63/2.64 Δ0.01, hasMediaFragmentInSrc:false) / Mirador INCONCLUSIVE — no consumer-owned AV control (hasConsumerPlaybackControl:false, native controls:true only).

Source: viewer-interop-report N2 + viewer-interaction-matrix.json + experiment-log #18

6. Mechanical resource-side validation IMPLEMENTED

Eight static checks (R-S1 viewBox, R-S3 Canvas dims, R-S4 same-aspect, R-S5 mapping, R-S6a MF grammar, R-S6b pct: alias SHOULD, R-S7 resource exclusions, R-S8a temporal permission) — 15/15 fixtures passing evidence/n6/, src/validator/. Consumer-side certification blocked pending a capable consumer.

Source: n6-implementation-report + evidence/n6/ + conformance-matrix

Method — falsifiable, blinded

  • Independent renderers: src/reference/ (Renderer A, iiif.ts/e14.ts shared core), src/blind/ (independent, interpretation-packet-driven), src/native/ (<img> pipeline). Blinding forbids sharing resolution logic; src/comparison/ is analysis-only. (AGENTS.md, consolidation-map §1.4)
  • E15 matrix: 10 SVG variants × 4 regions × 8 mechanisms = 176 cells, pixel-mask coverage≥0.8 K=0.25 (src/embedding-semantics/)
  • E16 composition: 8 fixtures × {fill,contain} + Mode A twins (public/manifests/e16/), Δ386.4 measured
  • E17 replication: 62/62 tri-engine via playwright.cross-engine.config.ts, mask verbatim, intrinsics + PAR collapse
  • N4 safe subset: P5a same-aspect decision (n4-safe-subset)
  • N2 consumer survey + D1 interaction probe: Ramp/Mirador unpkg bundles, consumer-owned click(.vjs-big-play-button) only — no video.play()/currentTime= writes
  • Evidence discipline: evidence-policy P-1 archived result sets, P-2 byte-unstable, P-3 auth regeneration
  • Validator N6: src/validator/ browser-free, T01–T15, evidence/n6/ 15/15

Source: capstone §4 + governance docs

AI-assisted methodology — short disclosure

AI systems were used as research-assistance tools under human direction and repository-level verification. ChatGPT Web (free) for planning/decomposition/critique/next-step prompts (no repo access) vs external OpenCode agents with repo/filesystem access for inspection/implementation/experiments/evidence/verification. The human was the responsible research operator (objectives, scope, accept/reject, governance, completion). AI assistance does not substitute for evidence — evidence remains traceable per evidence-policy.
